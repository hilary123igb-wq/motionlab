Every British Parliamentary debate hands out exactly six team points across four positions, so a position that is neither helped nor hindered averages 1.50. MotionLab measures how far each position drifted from that line, motion by motion.

Strength-adjusted goes further: before each round it ranks the four teams in a room by the points they had already earned, and compares each team's result to what that ranking implied. A motion then only looks one-sided if teams did better or worse than their own records predicted.

How this is built

Pipeline

Where the numbers come from

Results are read from each tournament's public Tabbycat REST API by following its own links: tournament → rounds → pairings → ballots. Results are not part of the draw, so every debate needs its own ballot request — roughly 830 for a tournament the size of WUDC. Each response is written to disk unchanged, stamped with its source URL and fetch time, and never requested twice.

Raw balance

For each debate, Gov − Opp = (OG + CG)/2 − (OO + CO)/2, then averaged over every room that ran the motion. Positive means Government benches scored more; negative means Opposition did.

Strength adjustment

The obvious objection to the raw number is that a motion can look one-sided just because stronger teams happened to sit on one side. So before each round, the four teams in a room are ranked by the points they brought into that round and assigned expected scores of 3 / 2 / 1 / 0, with teams on equal points sharing the places between them. Each team's residual is what it actually scored minus what that ranking expected. Averaging residuals by position gives the adjusted figure.

Two things make this safe. Only rounds before the one being measured are used, so the result being explained never feeds into the strength estimate. And the ranking happens inside a single room, so differences between brackets cancel — the question is only who was strongest of these four. Round 1 has no prior information, all four teams tie, and the adjusted figure falls back to the raw one; that is also the only randomly drawn round, so it needs no adjustment.

Reading the evidence dots

No significance tests are reported. What is reported is sample size, because a motion debated in 6 rooms cannot be measured as well as one debated in 91. A filled dot means 40 rooms or more, a grey dot 15 to 39, and a hollow dot fewer than 15. Treat hollow dots as suggestive at best.

The motion feature layer

Motion text is unstructured prose. A language model converts each motion into structured columns — topic, motion type, actor, geographic scope, how much outside knowledge it demands, how much mechanism a team must build — validated against a Pydantic schema so a malformed or invented answer is rejected rather than stored. Every extraction is cached on disk under a key that includes the prompt version, so the same motion is never sent twice and a given prompt always yields the same feature set. The model is never asked which side it thinks is favoured; that would put the answer into the features.

Scope and limits

Preliminary rounds only — elimination rounds draw from a pre-filtered field under different rules. The strength adjustment uses accumulated team points, which treats all wins as equal regardless of who they came against; a sequential rating would be better and is the obvious next step. Position allocation within a room is subject to Tabbycat's position-balance constraints, which this does not model. And with a handful of motions per tournament, comparisons between motions are far less certain than the figure for any single one.

Privacy

Speaker names and individual speech scores are stripped at the ingestion boundary, before anything reaches disk. MotionLab stores team, position and result only. No personal data is collected, stored or published.
